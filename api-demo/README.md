# Voice Button API demo

Отдельная страничка с микрофоном: она записывает звук **своего** браузера и
отправляет его в приложение Voice Button по HTTP. Приложение транскрибирует
присланный звук; локальный микрофон машины при этом не используется.

Ничего из этого не встроено в exe — это самостоятельный проект на Node.

## Запуск

1. В приложении: вкладка **API** → включить сервер, хост `127.0.0.1`, порт `8931`.
2. Здесь:

   ```powershell
   node api-demo/server.mjs
   ```

3. Открыть <http://127.0.0.1:8080/>.
4. Ничего не устанавливать не нужно: зависимостей нет, Node ≥ 18.

Адрес API по умолчанию `http://127.0.0.1:8931`; его можно поменять в поле
«API» на странице (запоминается в `localStorage`).

## Как идёт звук

- `getUserMedia` → `AudioContext({ sampleRate: 16000 })` → `AudioWorklet`.
- Раз в 250 мс страница отправляет `POST /api/record/audio?session=N` с телом
  `PCM16 little-endian, mono` (заголовок `Content-Type: application/octet-stream`).
- Приложение копит буфер и раз в ~1 с пере-декодирует его для живой
  транскрибации (для ONNX-моделей), а на `POST /api/record/stop` декодирует
  финальный текст.
- Результат страница забирает из `GET /api/record/text`, состояние и живой
  текст — из `GET /api/status`.

Частота дискретизации передаётся в `POST /api/record/start` (`sampleRate`);
приложение само приводит её к 16 кГц, поэтому подойдёт и 48 кГц.

## Ограничения

- **Микрофон в браузере работает только на `localhost`/`127.0.0.1` или по
  HTTPS.** По голому `http://<IP-адрес>` Chrome/Edge заблокируют
  `getUserMedia`. Для другой машины нужен либо HTTPS, либо клиент-скрипт,
  который шлёт PCM без браузера.
- Авторизации нет: кто дотянулся до порта API, может отправлять звук. Не
  открывайте API на `0.0.0.0` без доверенной сети.
- Одна сессия за раз. Если пользователь диктует в приложении, `POST
  /api/record/start` вернёт `409` — страница покажет «приложение занято».
- Пользователь может остановить API-сессию из приложения (кнопка Stop или
  хоткей): текст всё равно распознается и сохранится в истории, а страница
  увидит `stoppedBy: "user"`.

## Эндпоинты

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/help` | полный контракт API (JSON): эндпоинты, форматы, правила, примеры |
| GET | `/api/status` | состояние, кто пишет, `liveText`, `receivedMs`, `sampleRate` |
| GET | `/api/models` | модели этой сборки с флагом `ready` |
| POST | `/api/record/start` | `{"model":"Onnx/…","sampleRate":16000}` → `{sessionId}` |
| POST | `/api/record/audio?session=N` | тело: PCM16 LE mono |
| POST | `/api/record/stop?session=N` | финальная транскрибация |
| GET | `/api/record/live` | живой текст текущей сессии |
| GET | `/api/record/text` | текст последней сессии, `stoppedBy`, `error` |

CORS открыт (`Access-Control-Allow-Origin: *`), preflight `OPTIONS`
обрабатывается — страницу можно держать на любом локальном порту.

## Для интеграции и агентов

`GET /api/help` отдаёт самодокументируемый контракт: все эндпоинты с телами и
ответами, формат аудио, правила сессии, коды ошибок, quickstart и готовые
примеры на JavaScript, PowerShell и curl. Агенту достаточно прочитать этот
ответ, чтобы собрать плагин — бинарник ему не нужен.
